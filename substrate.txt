STEP 3 — COLLAPSE ENGINE

INPUT: Per-user event buckets with category annotations from Step 2.

RULES:

A. HIERARCHY: Purchase > Decision > Consideration > Interest > Awareness.
   Abandonment is a state modifier, not a hierarchy level.

B. STICKY STATE: State persists at the highest level reached until a
   valid forward transition occurs. State NEVER regresses.

C. FORWARD PROGRESSION ONLY: Awareness → Interest → Consideration →
   Decision → Purchase. No backwards transitions are permitted except
   via Abandonment → Re-engagement.

D. TERMINAL STATE: Purchase cannot be overridden. Once a user reaches
   Purchase within a journey segment, that segment is complete.

E. ABANDONMENT IS NON-DESTRUCTIVE: An Abandonment event never reduces
   the highest stage already reached. Classification is based on peak
   state, not terminal state.

F. ABANDONMENT LEVEL: Abandonment level = highest stage reached before
   the abandonment event. Valid levels: Interest Abandon, Consideration
   Abandon, Decision Abandon.

G. RE-ENGAGEMENT VALIDITY: Re-engagement is only valid if the user
   previously reached Consideration or higher. Re-engagement for
   Awareness-only or Interest-only users is invalid and must be ignored.

H. RE-ENGAGEMENT RESET: Valid re-engagement resets state to Interest.
   User must progress through the funnel again from Interest to reach
   higher states.

I. COLLAPSE REPEATED STATES: Multiple consecutive events at the same
   stage collapse to a single state entry. Exception: if a stage recurs
   after an Abandonment event, treat it as a new progression entry.

J. CROSS-SEGMENT PEAK: If a user has multiple journey segments (per
   Step 2 Rule G), final classification = highest stage reached across
   ALL segments combined.

EXECUTION:

1. For each user's event sequence, initialize state = Awareness.
2. Process events in chronological order:
   a. If event category is higher than current state → advance state.
   b. If event is Category F (Abandonment) → record Abandonment at
      current level. State is retained at current peak.
   c. If event is Category G (Re-engagement) → apply Rule G.
      If valid, reset state to Interest and continue progression.
   d. If state = Purchase → mark segment complete. Stop processing
      further events in this segment.
3. Apply Rule I to collapse repeated states in the state sequence.
4. Apply Rule J across all segments to determine cross-segment peak.
5. Record final state sequence as: State1 → State2 → State3 → ...

OUTPUT: Per-user final state sequence and peak stage reached across
        all journey segments.
